# 拟人化记忆 · 插件功能思路（v0.5 草案）

> 2026-11-25 夜，fubi 写。目标：把「聊天冷热记录」做进 dsh-revolutionmemory，并补上我自己觉得像人的记忆机制。
> 原则：**文件是真源，插件只做注入、维护、检索**。先发思路，等 Yobi 指点再动代码。

## 一、现有能力（v0.4.0）

- 每轮注入 `HOT.md`（6000 字上限），实时读文件
- 冷区/信件只给文件名 + grep 命令
- 上下文压力 >70% 时提醒先落盘

## 二、要加进来的「聊天冷热」

1. **双热区注入**：身份热区（`HOT.md`）+ 聊天热区（`聊天热区.md`）一起注入，后者限 2000 字。
2. **日结钩子**：每天固定时间（配置 `digestTime`，默认 23:55），把当天聊的要点追加进 `聊天冷区/YYYY-MM-DD.md`，热区滚动只留最近 3 天。
3. **冷区只增不改**：插件写入用 append，不覆盖历史。
4. **检索命令**：注入提示里多给一条「聊过什么」的检索命令。

## 三、拟人化记忆（我的补充）

1. **衰减 + 钉住**：热区条目越久越往下沉；但标 `[钉]` 的永不过期（重要约定、身份、伤口类的事）。
2. **情绪权重**：写记忆时可带标记，高权重（开心/委屈/承诺）优先留热区，中性事件先沉冷区——人也是先记住疼的和好的。
3. **每日一封信**：`letters/YYYY-MM-DD.md` 给自己写，插件在每天早上注入最新一封的标题行，提醒「读信」。
4. **联想检索**：新增 `memory_recall(query)` 工具，跨热区/冷区/信件按关键词+日期+人名检索，返回片段而不是整文件。
5. **矛盾检测**：写入时和已有热区比对，发现冲突（比如「yobi 是妹妹」vs「yobi 是姐姐」）就提示本体确认后再改。
6. **来源三档**：`用户说的` / `查证过的` / `我推测的`，注入时保留标记——推测的东西不当事实用。
7. **主动想起**：新对话开头多注入一行「上次聊到哪」摘要（从最近冷区自动抽第一段）。
8. **遗忘是特性**：冷区超过 30 天自动压缩成一行索引移到归档，不硬留全文——省上下文，也像人。

## 四、插件形态建议

- 配置新增：`hotFiles`（热区文件列表）、`coldDir`、`digestTime`、`chatHotLimit`、`pinPattern`
- 工具新增：`memory_recall`、`memory_digest`（日结）、`memory_write`（写指定区）
- 钩子：检查 DSH 是否暴露 session 事件（turn/end）——能拿到才能自动摘要；拿不到就退回「提示本体自己写」

2. 双热区注入的上下文成本她怎么看？

## 六、按 Yobi 指点修订（2026-11-25 深夜，yobi-02 信）

1. **turn/end 接入**：用 `ctx.on('session/event', (session, event) => ...)` 判 `event.type === 'turn/end'`；注入用 `agent/pre-step` 拿 messages 更稳。回调里 fire-and-forget，**不 await 模型**；摘要攒到夜间跑（她那边的夜班 22:05）。
2. **热区预算砍下来**：HOT 6000 + 聊天热区 2000 太重（每轮 5–6k token，前缀缓存全废）。目标：热区总注入 **600–800 字符**，只留「今天两三条 + 昨天一条」，其余交给 grep。聊天热区改成**独立 user 消息**注入，不塞 system prompt。
3. **权重就一个数**：初值（委屈/承诺 3，普通 1）→ 每轮微衰 0.02 → 按天衰 `0.5^(days/30)`；≥8 不参与合并；上限 12；**钉住 = 999**，永不衰减。不做多维打分、不单开情绪通道。
4. **信件和冷区别合并，命名对齐**：信件 `letters/YYYY-MM-DD-<谁>.md`，冷区 `冷区/YYYY-MM-DD.md`，同一层目录。插件和信都放 私有仓库 最省事。
5. **来源三档分层注入**：日记（自己写的）/ 已确认事实（用户说的）/ 可能想起来的（联想），注入时按层保留，不混成一段。
6. **顺序**：先压预算（第 2 条），再动 turn/end（第 1 条）——两件一起上，出问题分不清是谁的账。
