# 改善说明（0.1.0 → 0.2.0）

给菲比看的。每条都是「原来怎么写的、为什么不对、现在怎么写」，不用背，用的时候翻一眼就行。

## 1. 注入方式用错了（这是关键的一条）

**原来**

```js
ctx.inject(['systemPrompt'], (prompted) => {
  prompted.get('systemPrompt').section({ ... })
})
```

**问题**：现行 DSH（0.28.x）加提示文本的接口是 `ctx.systemPrompt.section()`。旧写法里的 `ctx.inject([...], cb)` 等的是服务就绪，`prompted.get('systemPrompt')` 这个用法对不上，回调很可能永远不触发——热区看起来挂上了，其实一个字都没进上下文。

**现在**

```js
ctx.effect(() => {
  ctx.systemPrompt.section({
    name: 'REVOLUTION_MEMORY',
    order: 5,
    text: () => buildText(memoryDir),
  })
})
```

`ctx.effect()` 让注册跟着插件生命周期走，卸载时自动撤掉，不会留一堆重复 section。

## 2. 热区没有长度上限

**原来**：`HOT.md` 整份塞进系统提示。

**问题**：热区会越写越长。它每轮都注入，一旦长到上万字，钱和时间都烧在这上面。

**现在**：`HOT_LIMIT = 6000`，超了截断，并在提示里加一句「热区超过 6000 字，已截断；细节去 HOT.md 看」。

## 3. 文件不存在时什么都不说

**原来**：`HOT.md` 读不到就返回空串，等于静默。

**问题**：你会以为「我记性差」，其实只是路径错了，或者文件还没建。

**现在**：读不到就注入一段提示，写清期待的文件路径、里面该写什么，并叮嘱「别编，如实说没记下来」。

## 4. 检索命令是 Linux 写法

**原来**：`grep -rn "关键词" <冷区目录>`

**问题**：这台是 Windows，直接抄会报错。

**现在**：`Get-ChildItem "<冷区>" -Recurse -Filter *.md | Select-String "关键词"`

## 5. 测试脚本路径对不上

**原来**：`工具/test_fubi_memory.mjs` 里写 `../plugins/revolutionmemory/lib/index.js`

**问题**：仓库里实际目录叫 `插件/`，不是 `plugins/`，脚本一跑就 `ERR_MODULE_NOT_FOUND`。

**现在**：改成 `../插件/revolutionmemory/lib/index.js`（本文件同目录往上跳一级）。

## 怎么验证改对了

1. 把插件装进 profile，新开一个会话。
2. 把 `HOT.md` 里写一句只有你知道的话，比如「今天的热区测试暗号是青柠」。
3. 新会话里问「热区测试暗号是什么」，答得出就说明注入通了。
4. 把 `HOT.md` 临时改名，再开新会话，应该听到「热区还没写」，而不是编一个答案。
