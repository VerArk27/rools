# 0.5.0：那次「死掉」的原因

一句话：插件在 `agent/pre-step` 上挂了个监听器，它是瀑布流事件，必须返回 `next(decision)`；我们那条只用来偷一个 session id，返回了 `undefined`。框架拿着 `undefined` 继续往下走，读 `decision.kind` 时崩——`Cannot read properties of undefined (reading 'kind')`，宿主一起倒下。

## 复现

`工具/sim.mjs` 里最后一段就是回放，跑一次能看到：

```
旧版 bug 回放：崩了 → TypeError: Cannot destructure property 'agent' of 'undefined' as it is undefined.
```

真实环境里的报错是读 `kind`，本质一样：事件载荷/决策是 `undefined`，而监听器没把 `next` 调起来。

## 改法

不再挂 `agent/pre-step`。上下文用量改成「读最近五分钟内有更新的会话缓存」，不需要知道 session id：

```js
const cachedSessionId = null   // 不再从事件里偷
```

`readPressure()` 本来就写好了退化逻辑：没有 id 就挑 mtime 最新的那个缓存文件，超过五分钟算过期。

## 顺带的两个修正

1. `mounted` 以前在 `ctx.inject` 调用完就置 true，即使服务里没有 `systemPrompt`，日志也会说「已挂载」。现在只有真的注册上 section 才置 true。
2. 没有可用注入接口时，日志明确写「热区未挂载」，不再假装成功。

## 自测

```
node 工具/sim.mjs
```

五个场景：正常、热区缺文件、没有 systemPrompt、热区超长、监听器回放。当前全过。

## 给以后加事件的规矩

- 瀑布流事件（`agent/pre-step`、`agent/request`、`llm/stream`、`tools/pre-execute`、`tools/execute`、`tools/post-execute`）里，不打算改决策就 `return next()`；要改就 `return {...decision, ...}`。
- 只想拿数据、不想影响流程，就别挂瀑布流，改用别的信号，或者干脆不拿。
